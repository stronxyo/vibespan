What I verified before writing any of this down

Research reports are only as good as their weakest unchecked claim. These are the load-bearing ones, tested on your machine — including two the researchers got wrong.

Confirmed A live session registry exists at ~/.claude/sessions/<pid>.json. Two files right now, carrying status, name, cwd, version and a heartbeat. The researcher only ever observed busy and flagged it uncertain — I see both busy and idle, so it is safe to colour-code.
Confirmed Your plan tier is readable offline. organizationRateLimitTier = "default_claude_max_5x", hasExtraUsageEnabled = true. Note it is not in seatTier or userRateLimitTier — both null here, which is where the report said to look.
Confirmed 103 days of usage history sits on disk in stats-cache.json — 79 sessions, 29,304 messages, 7 models, per-day per-model token counts, an hour-of-day histogram. Nothing visualises it.
Caveat That history file is eight days stale (lastComputedDate 2026-08-12) and its hourCounts has 16 keys, not 24 — it is sparse, and recomputed lazily. Anything built on it must show an "as of" date.
Confirmed A local HTTP endpoint needs no privileges. HttpListener binds http://localhost:9847/ from a non-elevated process with no netsh urlacl. This is what makes half the list cheap.
Confirmed Claude Code now auto-resumes when a usage limit resets (2.1.234, in your local changelog). Your reset countdown stops being trivia and starts predicting when work restarts by itself.
Refuted Painting the taskbar button is not available to us. The report suggests ITaskbarList3::SetOverlayIcon — but Vibespan sets WS_EX_TOOLWINDOW and therefore has no taskbar button at all. That style is exactly what removed the owner-window Z-order bug during the spikes, so it is not going away.
Not on Windows Cross-session messaging is macOS/Linux only. No SendMessage, no notify_when_idle, no messaging socket. Your session files advertise peerFeatures: ["notify_idle"], which is a capability claim, not a bound socket. Ignore that whole surface.
Bonus Our own JSON parser already earns its keep. ~/.claude.json contains two keys differing only in case, so PowerShell's ConvertFrom-Json throws on it outright. Vibespan's parser reads all 83 keys and 16 projects — the StringComparer.Ordinal choice made for the usage response pays off somewhere it was never designed for.

The five that change what this is

Everything else on the list makes Vibespan better. These make it a different category of thing.

ambient agent monitor

Multi-session tiles

A FileSystemWatcher on the session registry turns the widget into a live view of every Claude running on the machine — name, project, busy/idle, and how long each has been grinding. It stops being a usage gauge and becomes the thing you glance at to see what your agents are doing.

drops the credential handling

Statusline as transport

The status line already receives rate limits, context window, cost, model and effort every turn. Take delivery of that payload and Vibespan needs no OAuth token, no refresh rotation, no writing to the credentials file — the riskiest code in the project deletes itself for anyone who opts in.

the exact instant, not a percentage

Hook listener on 127.0.0.1

Hooks can be type: "http". Vibespan hosts a listener and Claude Code POSTs events to it — no subprocess per hook. StopFailure with error_type: "rate_limit" is the precise moment you hit the wall, and a permission prompt waiting in a background terminal becomes a desktop notification.

one number instead of two

Burn rate, not percent used

Show 1.4× — you are spending quota 1.4 times faster than the rate that exactly exhausts it at reset. Self-normalising across both windows, needs no reference to time remaining, and instantly actionable. An error budget is a quota that refills on a schedule; the mapping is exact.

everything else becomes free

A local /metrics endpoint

Twenty lines exposing the gauges in Prometheus text format hands you Grafana, Home Assistant, Polybar, Waybar, Rainmeter and every hobbyist ESP32 at once. Every physical-device idea below turns into somebody else's weekend project instead of your maintenance burden.

Where the data could come from

Vibespan currently has one source and it is the undocumented one. Every item here reduces that dependency.

Feeds and transports

Statusline-as-transport

Sno prior art

Install a status line that POSTs its whole stdin payload to Vibespan and prints a normal line. Live rate_limits, context_window, cost, model, effort, per session, with zero credential handling. Chain to any existing user status line rather than clobbering it.

HTTP hook listener

Sno prior art

One listener, many events. Drives a per-session state machine: idle → prompt submitted → running tool → stopped. Sub-10ms, no process spawns. Worth proving the response contract with a throwaway listener before building UI on it.

Prometheus scrape of Claude's own telemetry

S

Setting the exporter to prometheus opens a scrape endpoint on port 9464. Vibespan GETs it and parses text — no OTLP decoding at all. Real cost in USD, tokens split by cache-read and cache-creation, attributed per model, per skill, per MCP server.

Full OTLP receiver

M

The heavier version of the above, speaking http/json so no protobuf dependency is needed. Gets you per-skill and per-MCP-server cost attribution live. Rate limits are not exported over telemetry — the gauges must keep their existing source.

Ship as a Claude Code plugin

Mno prior art

A plugin bundles hooks, a status line, a subagent status line and a background monitor in one installable unit. It would replace the self-signed-certificate installer for the integration half entirely.

Reverse channel — the widget talks back

Mno prior art

A plugin monitor is a long-lived process whose stdout becomes a notification to Claude. Point one at a file Vibespan writes and the widget can say "your 5-hour window resets in four minutes — wrap up." The usage meter advising the agent is a genuinely new interaction.

Things already on disk that nothing reads

Multi-session tiles

Sno prior art

Watch the session registry directory. Every running Claude as a tile: name, project, busy or idle, elapsed. The biggest unbuilt idea in either report, and it needs no network and no permissions.

Stall detector

S

Time since the status last flipped, while busy — "this session has been grinding for 14 minutes." Time since the heartbeat, if large, means the process died without cleanup; grey the tile out rather than lying about it.

Plan and credits badge, offline

S

Label the gauges "Max 5×" and show whether extra-usage credits are enabled, read straight from the config file. Today that has to be inferred.

30-day history panel

S

Expand the hover into a sparkline of daily tokens stacked by model, from the local stats cache. One JSON parse, no network, 103 days already sitting there.

Cache-efficiency ring

Sno prior art

Cache reads as a share of all input tokens. Claude's own usage screen flags cache misses once they pass 10% of usage — so this is a directly actionable number, and nothing displays it live.

Cache-tier defection warning

Mno prior art

Transcripts distinguish 1-hour from 5-minute cache creation. The tier flips when you start drawing on usage credits — so Vibespan could warn "you have fallen off the 1-hour cache" before the user notices their usage accelerating.

Thinking-token meter

Mno prior art

Per-response thinking tokens are recorded in transcripts and surfaced nowhere in the product. A "how hard did it think this turn" bar ties directly to your effort setting.

Which project ate your week

Mno prior art

Group local prompt history by project and cross-reference against the weekly percentage. Plenty of tools do per-project cost; none answers "this repo consumed 40% of my quota." Note this file holds raw prompt text — read it only with that stated loudly.

MCP re-auth badge

S

A cache file lists servers needing re-login. "2 MCP servers need attention" is a one-line read and saves a confusing failure later.

Insights report launcher

M

The insights command writes an HTML report to disk. Watch for a fresh one and offer to open it. Nobody surfaces that file.

The gauge itself

Most of these come from domains that solved "a quota that refills on a schedule" decades ago — site reliability, aviation, and finance.

Reframings

Burn rate as a dimensionless number

M

1.0 is perfect pace, below 1.0 means you will leave quota unspent. The highest-information number you can fit in 200 pixels, and it works identically for both windows.

Time remaining as the headline

M

"About 3h 40m of Claude left at your current pace." Runway framing, in the unit people actually plan in. Percent is a unit nobody plans in.

Cost in tasks, not tokens

M

"Enough for about nine more medium tasks," from your own measured average. Pilots plan in destinations, not pounds of fuel.

Show only the binding constraint

M

Work out which limit bites first at current pace, show that one at full fidelity and demote the rest to a hairline. Two equal gauges make the user do the arithmetic on every glance.

Speedometer and odometer, separately

S

Rate and total are different questions. Every vehicle dashboard separates them; every quota UI conflates them, which is why "I've used a lot" and "I'm using fast" feel the same.

Auto-resume aware countdown

Snew in 2.1.234

Since Claude Code now continues automatically at reset, the countdown deserves a distinct state: not "you get quota back" but "work restarts by itself in 12 minutes."

Encodings for a 200-pixel canvas

The pace marker

S

A one-pixel tick where the fill would be if you spent evenly from window start to reset. Ahead or behind, at a glance, with no text — a burndown chart's ideal line compressed to a single pixel.

Bingo fuel — a reserve you refuse to dip into

Sno prior art

A user-set reserve, hatched at the end of the bar, alarming when you enter it rather than when you hit zero. Reframes the widget from "you are running out" to "you are spending your buffer" — a threshold you chose while calm.

Bullet graph instead of a bar

S

Actual, target and qualitative bands in about ten pixels of height. Invented specifically to replace dashboard gauges, which "display too little information and require too much space."

Reset as a depleting arc around the gauge

M

Superimpose time and quota so their relationship is the visual. This is the Time Timer's disappearing disk — the best-validated tiny-space time encoding there is.

Cooldown sweep

S

The same idea rendered as a radial wipe. Every gamer reads an ability cooldown with no legend at all.

Regen ghost segment

M

For the rolling window, draw the incoming refill as a lighter ghost ahead of the fill — a stamina bar that shows regeneration, not just drain. "Wait twenty minutes and you get some back" is real, and currently invisible.

Sparkline with one emphasised endpoint

S

Word-sized, no frame, no axis, a single coloured dot for now. Add ticks at reset boundaries or the sawtooth is unreadable.

Horizon chart for the weekly series

M

Fold the series into layered bands so a week fits in twelve pixels. Below a measured chart-height threshold these beat line charts on estimation accuracy — and you are far below it.

Non-linear final decile

S

Give the last 10% of quota 25% of the pixels. Fuel gauges and VU meters both put resolution where decisions happen. Say so in the tooltip.

Time-of-day heat strip

M

A three-pixel, 24-cell strip showing when in the day you burn quota. The most "I didn't know that about myself" visual available, and the data is already on disk.

Personal baseline band

M

A grey band showing your own typical range for this hour and weekday. Deviation from your normal is the signal; absolute numbers are noise.

Forecast wedge, not a point estimate

M

Projected end-of-window usage as a translucent conservative-to-optimistic wedge past the current fill. Honest about uncertainty, which is what makes it trustworthy.

Never colour alone

S

At thresholds, change shape or pattern too — hatching, a notch, a corner cut. Already half-done via the tick and the critical glyph; worth finishing as a rule rather than a habit.

Alerting that survives being left on

The difference between a widget people keep and a widget people close.

Multi-window burn-rate alerting

M

Never alert on an instantaneous rate. Require a short and a long window to both exceed a threshold, with the short one about a twelfth of the long. One heavy agentic run spikes you to 20× for four minutes; a naive widget screams and a good one does not.

A notification-level ladder in code

S

Every event maps to ignore / change-blind / make-aware / interrupt / demand, and only two events in the whole application are allowed above make-aware. Default is change-blind.

Rate-limit wall detector

Sno prior art

A hook fires with an explicit rate-limit error type at the exact instant you get cut off — far better than inferring it from a percentage that updates every five minutes.

Permission-prompt escalation

Sno prior art

Flash when a background terminal is silently waiting on you to approve something. This is the loudest real complaint about running parallel sessions.

Interruption-aware delivery

M

Hold non-urgent alerts during a detected deep-work stretch and deliver at a natural boundary. Recovery from an interruption averages around 23 minutes; the widget's superpower is being seen without interrupting.

The under-use alarm

Sno prior art

Near the end of a window with quota clearly unspent: "you are leaving quota on the table — go start something ambitious." Every tool treats over-use as the only failure. This is the funniest and kindest thing a usage widget can say.

Self-imposed interrupt budget

M

The widget may spend at most N interrupts a day and shows how many remain. A tool that visibly rations its own nagging is disarming — and it forces the interrupts to be good.

Three distinct failure states

S

Stale, offline, auth-expired and rate-limited are four different problems wearing one costume today. Splitting them is cheap and buys real trust.

Behaviour, not just information

Every usage tool on the market stops at reflection. The research on personal informatics is blunt that the action stage is where behaviour actually changes.

An action attached to every state

M

One design rule: the widget is never allowed to show a state without a concrete suggested action. That single constraint is the difference between informative and useful.

A policy table, not just a number

M

User-authored rules — "at 85% weekly, default to Sonnet"; "at 95%, turn on Do Not Disturb." Site reliability practice is that a budget's value comes from the policy attached to it, not the number. Almost no consumer tool copies this.

If-then plans as a first-class object

M

Let the user write an implementation intention that the widget surfaces at the trigger moment. This is the most evidence-backed idea on the whole list.

Envelope budgeting

L

Split the weekly quota into named envelopes — work, side project, messing about. Overspending one visibly steals from another. The friction of moving quota between envelopes is the mechanism.

Overdraft preview

M

Before a big run: "a typical refactor costs about 6% — you would enter the reserve at 14:20."

Monday review card

M

One card, once a week, six numbers. Reflection works at a cadence; continuous nagging does not.

Self-scoring forecasts

M

Predict end-of-window usage each morning, score it at each reset, show calibration over time. Makes the projection trustworthy rather than decorative.

Explicitly no punishing streaks

S

The streak trap is well documented — unforgiving counters produce guilt and churn. If you want a consistency signal use a band, not a streak, and say "no streaks, no guilt" in the README as a positioning statement.

A real observe-only switch

S

One toggle: never nudge, never colour, never sound, keep all history. Pressure backfires for some people and awareness alone works. Letting the user choose their mode is both kind and rare.

Reach

Ordered by delight per hour of work. The local endpoint and a webhook make most of this configuration rather than integration.

Outbound webhook on tier change

S

One config field. Instantly wires into phone push, Home Assistant, automation tools, Discord and Slack without you integrating with any of them.

Run a script on threshold crossing

S

With the state in environment variables. Combined with the endpoint and webhook, this is the entire extensibility story in an afternoon.

Phone push when the tank refills

S

The most useful notification a quota tool can send, because it tells you to come back rather than to stop.

Discord rich presence

S

"Vibespan — 62%, resets in 1h12." No authentication; it talks to the local client. Every user passively advertises the widget.

Home Assistant auto-discovery

M

Publish once and the widget appears as a sensor with no user configuration, from which people wire it to lights, speakers and dashboards themselves.

Desk lamp or keyboard lighting as the gauge

M

Your keyboard underglow drifting amber as the week burns is the single most "I didn't know a widget could do that" output available — and it is nearly free once the script hook exists.

Stream Deck key and dial

M

The key face is the gauge; on a model with dials, the touch strip shows the sparkline and the dial sets your reserve.

Screenshot-safe mode

S

A hotkey that keeps the shape and blanks the numbers, so screen shares do not leak your plan tier or spend. Then the inverse — a transparent browser source so streamers can deliberately show it.

E-ink or pixel-display desk gadget

M

Several of these devices work by fetching an image from a URL, so serving one endpoint makes the widget hardware. Battery life in months, and the calmest possible surface.

A real analogue needle

M

A six-dollar microcontroller and a panel voltmeter. Nothing you can render competes with a moving needle for charm, and the write-up alone would carry the project.

Character

The line, which both the design literature and the gamification backlash agree on: optional, occasional, non-blocking, never attached to a penalty.

Milestones as typography, not confetti

S

The border draws itself once, over 600ms. That is the whole celebration. Restraint reads as quality.

One sound, and make it the good news

S

A chime at reset, not at the warning. Rewarding sounds age far better than warning sounds.

Weather-report line

M

"Heavy usage moving in — at this rate you reach the reserve around 3pm; clear after the 6pm reset." Forecast framing is friendlier and more actionable than a percentage.

Sigil of the day

M

At each rollover, mint one small glyph encoding the day's shape — peak hour, total, pace — and collect them into a year grid. A contribution graph made of characters.

Your Claude Code birthday

S

Yours is 20 October 2025, across 358 startups and 29,304 messages. A once-a-year card, entirely from local data, zero risk.

A pet that is never sad

M

If there is a creature, mood maps to headroom and the worst state is "asleep," not "dying." Sleepy is charming; guilt is churn.

Across-the-room mode

S

Drop all text, render one colour field and a fill, readable at three metres. Pre-attentive processing is the point of an ambient device; text defeats it.

Screen-edge hairline

M

The calmest possible rendering: a two-pixel line along the bottom of the display whose length is the fill. A bezel, not a widget. This is the mode people screenshot.

If I were picking

The one place on this page where order carries information.

  1. Local endpoint, webhook, script hook

    A weekend, and half this page becomes somebody else's project instead of your backlog.

  2. Multi-session tiles

    No network, no permissions, no prior art, and it changes what the product is. The registry is already on disk and updating.

  3. Statusline as transport

    Free live data per session and the credential-handling code — the riskiest part of the project — becomes optional.

  4. Burn rate, pace marker, bingo fuel, binding constraint

    The conceptual reframe. This is what makes it a fuel gauge rather than a usage meter.

  5. Multi-window alerting and the notification ladder

    What makes it trustworthy enough to leave running forever.

  6. History panel and cache-efficiency ring

    103 days are already on disk. One JSON parse.

  7. Under-use alarm, weather line, reset chime

    Character, cheap, and nobody else has the first one.

Don't build these

Cross-session messaging. Not available on native Windows at all. The capability string in your session files is an advertisement, not a bound socket.
Rate limits from telemetry. Quota is explicitly not exported over OpenTelemetry. The gauges must keep their current source.
Taskbar button progress. Vibespan has no taskbar button by design — that is what fixed the Z-order bug. The tray icon is the equivalent surface.
The failed-telemetry spool. Anthropic's own internal analytics, present only when upload fails, with no stability contract.
Anything in the daemon directory. That is key material.
Prompt and API body logging. Telemetry can be told to include your raw prompts. Never set those, and say so in the README.
